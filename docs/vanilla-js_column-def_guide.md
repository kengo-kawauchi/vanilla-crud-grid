## HTML5とVanilla JSの入力バリエーション役割分担(ベストプラクティス)

### 簡易的な説明

- HTML5バリデーション（ブラウザ標準）
  - 手軽な水際対策（HTML5）
- Vanilla JS（独自実装のJavaScript）の定義層
  - 厳密なビジネスロジックの保証（JS）

### それぞれの入力チェックの具体例

- HTML
  - 文字種制限(type="email" や type="number")
  - 必須チェック(required)
  - 範囲チェック(min, max, maxlength)
  - 簡易フォーマットチェック(pattern="[0-9]{3}-[0-9]{4}")
- Vanilla JS定義層
  - 相関バリデーション
  - 非同期バリデーション
  - 動的バリデーション

### 役割分担のベストプラクティス

ハイブリッドで実装する場合、HTML5側のデフォルト挙動をリセットしつつ、その検証結果（ValidityState）をJSで利用する方法が最もスマート。

1. HTMLにルールを記述する:  
`required` や `pattern` などの属性は、アクセシビリティ（スクリーンリーダー対応など）の観点からもHTML側に書いておく

2. ブラウザ標準のUIを無効化する:  
`<form novalidate>` を付与して、ブラウザ独自のポップアップが表示されるのを防ぐ

3. JSで checkValidity() を呼び出す:  
JS側で `element.validity` を参照し、HTML5が判定した結果 ( `valueMissing` や `patternMismatch` など) をトリガーにして、独自の美しいエラーUIを構築する

4. 複雑なロジックはJSで追加する:  
HTML5でカバーできない相関チェックなどは、JS側で `setCustomValidity()` を使うか、独自のエラーフラグを立てて処理する

### 各レイヤーの具体的な役割

#### HTML5バリデーションの役割

- 役割
  - 主に「ユーザーが間違った入力をするのをその場で防ぐ（UXの向上）」ために使います。
- 使用例
  - 入力形式の制限: type="email" や type="number" による、キーボードの出し分けや文字種の制限。
  - 単純な必須チェック: required による空文字のブロック。
  - 最小・最大・文字数制限: min, max, maxlength による基本的な範囲チェック。
  - 簡易的なパターンマッチ: pattern="[0-9]{3}-[0-9]{4}" のような、標準的な正規表現でのフォーマットチェック。

#### Vanilla JS定義層の役割

- 役割
  - 主に「ビジネスルールに則っているかの検証（ロジックの保証）」と「柔軟なUI制御」に使います。
- 使用例
  - 相関バリデーション: 「パスワード」と「パスワード（確認）」の一致チェックや、「開始日」が「終了日」より前かどうかの検証。
  - 非同期バリデーション: 「すでに登録されているユーザー名か」をAPIで確認するチェック（fetchなどを利用）。
  - 動的なバリデーションの変更: 別の選択肢（例：国籍で「日本」を選んだ場合のみ、フリガナを必須にするなど）に応じたルールの切り替え。
  - エラー表現の統一・多言語化: ブラウザごとに見た目や文言が変わるのを防ぎ、デザインシステムに合わせたエラー表示を行う。

## Vanilla JSでの列定義

### 列定義の内容案

- 必須
  - key
  - label
  - width
  - align
  - required
  - maxlength
  - type
- 必要になったら追加
  - visible
  - editable

### 実装サンプルコード

```js
const columns = [
  {
    key: "employeeName",
    label: "社員名",
  
    width: "16rem",
    align: "left",
  
    required: true,
    maxlength: 50,
  
    type: "text"
  }
];
```

### オブジェクトではなく配列で列定義する理由

列定義にオブジェクト（連想配列）ではなく配列を採用する主な理由は、以下の3点。

1. 順序（並び順）の保証
   - オブジェクトは仕様上、キーの順序が保証されない場合がある。
   - 配列は要素の順序が厳密に保持されるため、画面上の左から右への列の並び順を直感的に制御できる。

2. 繰り返し処理の容易さ
   - `map` や `forEach` を使って、テーブルのヘッダーやセル（`<th>`, `<td>`）のレンダリング処理をループで簡潔に記述できる。

3. 順序ベースの拡張性（非破壊的な操作）
   - 途中に新しい列を追加したり、特定の列の順番を入れ替えたりする操作（`splice` や `sort` など）が容易。
